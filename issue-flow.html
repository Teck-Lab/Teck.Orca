Teck · Orca + OMP workflow

From issue to verified delivery

The planner creates the execution plan. The orchestrator checks and dispatches it. Executors own delivery, using native helpers wherever useful. The same pattern applies inside sub-issues.

Issue lifecycle

The assigned planner creates/reuses execution issues and dependencies. The orchestrator checks the graph, dispatches ready work and owns acceptance.

Inside an executor

An executor can plan and delegate recursively. Native helpers use OMP lifecycle; the parent owns permissions, evidence and acceptance.

Dependency waves

Start every independently ready branch within the configured capacity. Do not add dependencies merely because work shares a parent issue.

Missed blockers

Diagnose first, then revise only the affected part of the plan. Unrelated work continues; a missed assumption does not reset the whole feature.

Every role can use native helpersPlanners, researchers, executors, reviewers and the orchestrator may delegate. Research helpers stay read-only; the assigned planner owns canonical plan writes.
One plan writer at a timeThe coordinator pauses its plan edits while the planner is writing. Create durable sub-sub-issues when useful; ordinary helpers need no extra issue or Orca Dispatch.
