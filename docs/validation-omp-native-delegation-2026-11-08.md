# OMP native delegation and review validation

The Orca executor delegates its implementation to the managed `implementation-worker` native OMP task. Its actual turn must start before parent implementation, execution, debugging, unrestricted eval or goal completion is allowed. Queued task receipts do not release that gate. The parent owns scope, integration, verification and the exact Orca Task/Dispatch settlement. Independent file ownership permits parallel helpers; a small assignment can use one helper.

The independent Orca reviewer runs bounded `correctness-reviewer` and `security-auditor` tasks in parallel for code/deployment changes, then validates and deduplicates their evidence into one verdict. Documentation-only changes may omit the security helper with a reason. This uses the stable-diff and actionable-finding pattern documented for [OMP review](https://omp.sh/docs/review), rather than adding an interactive `/review` pass. PR-URL review expects authenticated `gh`, which is outside our App-MCP publication workflow. The ordinary security task works with the existing model route; native [`/security`](https://omp.sh/docs/security) requires stored OAuth authentication and is not enabled for the current API-key route.

The implementation preset enables the existing [native advisor](https://omp.sh/docs/advisor) at turn checkpoints; the coordinator, reviewer and read-only review helpers keep background advisors off. Only Supervisor is enabled, with one bounded note and no backlog wait. Its model follows the configured advisor role. Installed OMP 18.16.0 applies the preset advisor override after its default subagent disable. Native Hindsight children reuse parent memory state and skip redundant automatic first-turn recall/retain; global automatic memory remains enabled.

All roles retain [native task](https://omp.sh/docs/subagents) and wait. Unrestricted eval remains executor-only because it can execute arbitrary Bun/JS/shell. Read-only helpers cannot obtain editing/publication through nested tasks, advisor identities, LSP mutation, structural edits or mounted `xd://` tool routes. Ancestor revocation and shutdown propagate to running descendants. These are trusted-agent workflow controls within the shared sandbox, not process or filesystem isolation.
